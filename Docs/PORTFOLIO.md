# 재의 길 — 포트폴리오 마감 계획

> 마지막 갱신: 2026-08-20

이 문서는 `재의 길`을 프로그래머 포트폴리오 대표작으로 마감하기 위한 작업 계획입니다.
게임 소개와 현재 기능은 루트 `README.md`, 구현 현황은 `PROJECT_CONTEXT.md`를 기준으로 합니다.

## 포트폴리오 전체 구성

전체 포트폴리오는 네 개의 3D 기능 프로토타입과 한 개의 2D 완성작으로 구성합니다.

| 프로젝트 | 증명하는 것 |
| --- | --- |
| 3D TPS 전투 | 전사 캐릭터, 일반 몬스터와 보스 AI |
| 3D 공포 게임 | 3×3 공간 전환과 추격자 |
| 3D 도시 이동 | 물리 기반 웹스윙과 공중 전투 |
| 3D 오픈월드 | 물리 기반 오토바이 주행 |
| 2D `재의 길` | 여러 시스템의 통합과 마감 |

네 개의 3D 프로젝트는 각각 전투·공간·캐릭터 물리·차량 물리 구현력을 보여줍니다.
`재의 길`은 기능 하나를 더 증명하는 프로젝트가 아니라, 여러 시스템을 충돌 없이 연결하고
기획부터 빌드·플레이테스트·마감까지 끝낸 경험을 증명하는 대표작으로 사용합니다.

첫 화면에는 `재의 길`을 대표 완성작으로 배치하고, 네 개의 3D 프로젝트는 `Technical Prototypes`로
묶어 각 30초 영상과 핵심 문제 해결 사례를 보여줍니다.

**주의**: 3D 프로토타입 네 개가 모두 미완인 상태로 나열되면 "끝내지 못하는 사람"으로 읽힐 수
있습니다. `재의 길` 하나를 확실히 끝낸 뒤 나머지는 영상과 문서 한 장으로 압축합니다.

## 판단 기준

평가 기준은 기능 수가 아니라 완주 가능성과 통합 완성도입니다.
새 전투 시스템, 물리 기능, 유물·스킬·적 종류 추가는 아래 마감 작업보다 우선하지 않습니다.

## 작업 순서

### 0단계 — 저장소 위생 (약 1시간, 효과 대비 최우선)

저장소를 처음 여는 사람의 인상을 가장 크게 바꾸는 단계입니다. 2026-08-20 기준 실측:

| 항목 | 현재 상태 | 조치 |
| --- | --- | --- |
| `NeoDunggeunmoPro-Regular96.asset` | 단일 파일 37MB, 저장소 최대 | TMP Dynamic 아틀라스로 전환 |
| TextMesh Pro Examples & Extras | 285개 파일 추적 중 | 삭제 후 `.gitignore` 등록 |
| `_ArtBackup/` | 9개 파일 추적 중, `.gitignore` 미등록 | 추적 해제 + `.gitignore` 등록 |
| `SampleScene.unity` | 미사용 | 삭제 |
| `*_raw` 계열 이미지 | 148개 | 최종본이 있는 것부터 정리 |
| 미사용 패키지 | visualscripting, multiplayer.center, timeline 등 | `manifest.json`에서 제거 |

백업 폴더가 커밋되어 있는 상태는 실제 실력과 무관하게 감점 요인이 됩니다.
git 히스토리 재작성은 하지 않습니다. 앞으로만 정리해도 충분하고 위험만 큽니다.

### 1단계 — 루프 고정과 검증 구조

1. 일반 방 3개 → 보스 방 → `Result` → 재시작까지 막히지 않는 전체 루프
   - 씬 Inspector 연결에 의존하지 않도록 방 순서를 직렬화 데이터로 고정합니다.
   - 씬을 수정할 때마다 진행이 깨지는 상태를 구조적으로 없애는 것이 목적입니다.
2. `asmdef` 분리 — 현재 0개입니다. 테스트 어셈블리의 전제 조건이므로 테스트보다 먼저 합니다.
3. 핵심 테스트 3종 — 유물 재계산, 방 순환, 보스 페이즈 전환

### 2단계 — 보여줄 수 있는 산출물

1. 다운로드 가능한 Windows 빌드
   - 배포는 itch.io를 우선합니다. 다운로드가 한 번에 끝나고 플레이 기록이 남아
     플레이테스트를 했다는 근거가 됩니다.
2. 처음부터 보스 처치까지 보여주는 90초 플레이 영상
3. README 상단의 GIF·스크린샷·빌드 링크·담당 범위

### 3단계 — 사운드

영상에서 소리가 없으면 바로 드러나므로 최소 범위를 먼저 넣습니다.

1. 공격·피격·사망·상자 효과음 4종
2. 이후 대시, 보스 전환, UI 효과음과 BGM

사운드는 게임으로서의 완성도를 채우지만 프로그래머 역량을 증명하지는 않습니다.
그래서 1단계보다 뒤에 둡니다.

### 4단계 — 코드를 읽게 만드는 장치

스크립트가 96개입니다. 전부 읽어줄 사람은 없으므로 읽을 곳을 지정해야 합니다.
실제로 설계 판단이 들어간 지점은 다음 세 곳입니다.

- **유물 재계산** — `RelicData`가 정의를, `RelicInstance`가 런마다 결정된 실수치를 소유하고,
  장착이 바뀌면 기본값에서 전부 다시 계산합니다. 보정치 누적 버그를 구조로 막은 사례입니다.
- **방 진행 이벤트 체인** — `RoomController` → `RoomDoorState` → `RoomExitTrigger`
- **보스 페이즈 전환** — 체력 50%에서 `AnimatorController`를 교체하는 2페이즈 구조

README에 짧은 흐름도와 파일 링크를 함께 둡니다.

또한 `Assets/Editor`의 자동화 도구 21종(스프라이트 슬라이서, 방 진행 빌더, 유물 빌더,
임포트 규칙 등)은 현재 README에 한 줄로만 언급되어 있습니다. 1인 개발에서 반복 작업을
도구로 없앤 기록이므로 별도 섹션으로 분리합니다.
