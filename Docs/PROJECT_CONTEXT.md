# 재의 길 — 프로젝트 컨텍스트

> 마지막 갱신: 2026-09-04

이 문서는 새 작업이나 새 대화에서 프로젝트의 현재 상태를 빠르게 파악하기 위한 요약입니다. 과거 작업 과정은 `DEVELOPMENT_LOG.md`에만 남기고, 여기에는 현재도 유효한 사실과 다음 행동만 유지합니다.

## 한 줄 요약

영구 성장 없이 유물 시너지로 한 판을 완성하는 2D 탑다운 픽셀아트 던전 슬래셔 로그라이크입니다.

## 설계에서 바꾸지 않을 것

- 죽으면 언락·영구 강화 없이 런을 완전히 초기화합니다.
- 반복 동기는 유물 조합과 전투 숙련이 담당합니다.
- 재시작은 상태를 수동 초기화하지 않고 게임 씬을 다시 로드하는 방식입니다.
- 게임플레이 아트는 회색·숯색을 바탕으로 주황 잉걸만 강조색으로 씁니다.
- 공격은 피해보다 예비동작과 회피 가능성이 먼저 읽혀야 합니다.
- 에디터 도구는 메뉴에서 명시적으로 실행하며 씬을 자동 저장하지 않습니다.
- 기존 Unity 에셋을 교체할 때 `.meta`와 GUID를 유지합니다.
- 저장 금지의 대상은 게임 진행(영구 성장·언락)이지 플레이 환경이 아닙니다. 볼륨·화면·키 설정은 저장합니다.

## 현재 플레이 흐름

1. `Title`에서 게임 시작
2. `Game`의 **튜토리얼 방**에서 조작을 익히고 아래 문으로 나감
3. 던전 방 전투 → 적 전멸 후 보상 상자 → 개봉 후 문과 출구 활성화
4. 상자에서 **보스 열쇠** 4종을 모으면, 다음 보상을 챙길 때 **부서진 문**이 열림
5. 부서진 문으로 나가면 **보스 방** 진입
6. 보스 처치 → 클리어 유물 드롭 → 획득 시 문 개방 → **문 통과 시 승리로 런 종료**
7. 플레이어가 죽으면 패배로 런 종료
8. `Result`에서 결과 표시 및 재시작

튜토리얼 방과 보스 방은 별도 씬이 아니라 `Game` 씬 안의 방입니다. 씬을 나누면 HUD·인벤토리·플레이어를 복제해야 하고, 복제본이 원본과 어긋나는 위험이 생깁니다.

보스 진입 조건은 방 번호가 아니라 **열쇠**입니다. 두 조건을 같이 두면 열쇠를 다 모았는데 방 번호가 먼저 걸려 보스가 나오고, 어느 쪽으로 갔는지도 알 수 없어서 방 번호 조건은 걷어냈습니다.

승리 흐름은 코드가 모두 연결됐지만 **결과 화면까지 완주 검증은 아직 하지 않았습니다.**

열쇠를 다 모으면 **그 방에서 바로** 부서진 문이 열립니다. 예전에는 보상을 한 번 더 챙겨야 했는데,
상자가 "열렸다"와 "보상을 손에 넣었다"를 신호 둘로 나누면서 같이 풀렸습니다.

## 구현된 시스템

### 코어와 전투

- `GameFlow`, `RunManager`, `RunResultData`로 씬 흐름과 런 결과 관리
- `Health`, `DamageInfo`, `DamageHitbox`를 플레이어와 적이 공유
- 플레이어 이동, 대시, 넉백과 실제 속도 기반 애니메이터 연동
- Ctrl 기본 공격과 Q/W/E/R 스킬
- `SkillData` 상속 구조로 근접·투사체·장판 스킬 분리

### 방과 적

- 잿불 망령: 배회 → 추격 → 예비동작 → 돌진 → 회복 상태 머신
- `ObjectPool<T>` 기반 적 재사용
- `RoomController`, `RoomDoorState`, `RoomExitTrigger`, `RoomSequenceController`
- 전멸 → 상자 → 문 개방 순서를 이벤트로 연결
- 방 이동 시 플레이어의 Rigidbody2D 속도 초기화

### 유물과 인벤토리

- 유물 14종: 일반 10종과 보스/진행 유물 4종
- `RelicData`는 정의, `RelicInstance`는 런마다 결정된 실제 수치를 소유
- 유물 수치는 정의된 범위 안에서 런마다 무작위 결정
- 보관함과 장착 슬롯 3개 분리
- **보스 열쇠 4종은 전용 칸 4개**를 따로 씀 — 진행 표식이 전투 칸을 뺏으면 열쇠를 모을수록 약해집니다
- `T`로 여는 보스 열쇠 화면. 칸을 눌러 빼면 보관함으로 돌아가고 사라지지 않습니다
- 장착된 유물만 효과 적용
- 장착 변경 시 기본값에서 모든 보정치를 다시 계산
- `Health`와 `PlayerStamina`는 기본 최대치 + 유물 보정 구조
- 인벤토리를 열면 시간이 멈추며 `I` 또는 `Tab`으로 닫음

### 입력

- 조작 액션 전부를 `InputBindings`가 소유합니다. 컴포넌트는 꺼내 읽기만 합니다
- 액션 맵은 부팅 때 켜고 끄지 않습니다 — 켜져 있어도 읽는 쪽이 없으면 아무 일도 안 일어납니다
- **인스펙터에서 키를 바꿀 수 없습니다.** 그 자리는 설정 화면입니다. 두 곳에서 바꾸면 어느 쪽이 맞는지 정할 수 없습니다
- `InputCatalog`는 조작의 이름과 묶음만 들고, 키 문구는 실제 액션에서 읽습니다
- 이동은 **방향키만**입니다. `W`가 스킬 2와 겹쳐서 WASD를 뺐습니다
- 기본값: 방향키 이동 / `Shift` 대시 / `Ctrl` 기본 공격 / `Q W E R` 스킬 / `F` 상자 / `I`·`Tab` 보관함 / `T` 열쇠 / `ESC` 설정
- `ESC`는 바꿀 수 없습니다. 옮길 수 있게 하면 창에서 못 나오는 상태를 스스로 만들 수 있습니다
- 키 겹침은 **같은 맥락끼리만** 따집니다. 스킬 4와 결과 화면 재시작은 둘 다 `R`이지만 두 화면이 동시에 뜨지 않습니다
- 겹치면 **막지 않고 비웁니다.** 이미 쓰는 키라고 거절하면 왜 안 되는지 모른 채 다른 키를
  계속 눌러보게 됩니다. 비우고 무엇을 비웠는지 알려주면 "저기도 다시 정해야겠구나"가 보입니다
- **키를 뺏긴 자리는 비어 있을 뿐 사라지지 않습니다.** 그 자리에 다시 아무 키나 넣을 수 있어야
  합니다. 2026-09-04까지는 그러지 못했습니다 — 자리를 `effectivePath`로 찾다 보니 비워진 자리를
  건너뛰어 `-1`이 나왔고, 키보드 자리가 하나뿐인 스킬 `Q W E R`은 한 번 뺏기면 **초기화 말고는
  되돌릴 방법이 없었습니다.** 지금은 `path`(원래 경로)로 자리를 찾습니다
- **키를 글자로 적어둔 UI가 없어야 합니다.** 스킬바·튜토리얼·결과 화면은 전부 실제 바인딩에서 읽습니다

### 설정과 시간 정지

- `PauseGate`가 `Time.timeScale`을 만지는 **유일한 곳**입니다. 열린 화면을 세고 스택이 빌 때만 시간을 되돌립니다
- 화면을 전환할 때는 **먼저 열고 뒤에 닫습니다.** 반대로 하면 스택이 잠깐 비어 시간이 튑니다
- `SettingsScreen`은 일반/조작 두 탭이고 Title과 Game이 같은 화면을 씁니다
- Game은 `ESC`로 열고, Title은 구석의 버튼으로 엽니다. 타이틀의 `ESC`는 예전부터 게임 종료라 겹칠 수 없습니다
- 창 크기는 해상도 목록이 아니라 **정수 배수**(2/3/4배)입니다. 비정수배는 픽셀이 일렁입니다
- `GameSettings`가 `PlayerPrefs`에 저장하고 부팅 때 한 번 적용합니다
- **볼륨은 아직 들을 소리가 없습니다.** `GameAudioMixer`를 만들면 배선 없이 살아납니다
- **창 크기·전체화면은 에디터에서 확인할 수 없습니다.** Game 뷰가 `Screen.SetResolution`을 무시합니다

### 재의 왕 보스

- 1페이즈: 거대한 중갑 재의 왕
- 체력 **70%**에서 갑옷이 무너지고 여성형 진체인 2페이즈로 전환.
  두 페이즈의 몫을 일부러 어긋나게 나눴습니다 — 1페이즈가 전체의 30%(27), 2페이즈가 70%(63).
  반반이면 2페이즈가 "체력이 한 번 더 있는 1페이즈"가 되는데, 실제로 어려운 쪽은 뒤입니다
- 전환은 **Timeline 3.125초 연출**(`BossTransition.playable`)입니다. 시간표의 주인이
  타임라인 에셋 하나뿐이라 코드와 클립의 시간이 갈라질 자리가 없습니다.
  `BossTransitionSequence`는 재생과 시그널 중계만 하고 시간을 세지 않습니다
- 2페이즈 핵심 의미: 갑옷 속 인물이 아니라 재가 왕의 형상을 직접 얻은 상태
- 거리 기반 패턴 선택과 페이즈별 AnimatorController 분리
- 패턴 3종 — 내려찍기(옆으로 피함), 잿불 파도(사이로 피함), **재 폭발**(멀어져서 피함)
- 재 폭발은 2페이즈 전용. 반경 12로 방 바닥 대부분을 덮고 **네 모서리만 안전**하다
- 판정은 그림(좌우 2방향)이 아니라 **실제 방향**을 따름 — 내려찍기 상자를 조준 방향으로 회전
- 공격 시간은 **클립 길이 그대로**, 2페이즈는 `phase2MotionScale`(0.8)로 줄임 (2P 클립이 15fps)
- 2페이즈에서 몸통 콜라이더 **폭만** 0.87배로 줄임 (시트를 재보면 높이는 같고 폭만 줄었다)
- 보스 프리팹: `Assets/Project/Prefabs/Enemy/BossAshKing.prefab`
- 보스 로직: `Assets/Project/Scripts/Enemy/EnemyBoss.cs`
- `EnemyBoss.OnValidate`가 인스펙터 값의 모순을 경고한다 — 시전 사거리가 물러나는 거리보다
  작으면 그 패턴은 영영 안 나오고, 닿는 거리보다 크면 시전해도 헛친다
- **죽는 한 대는 `OnDamaged`에서 돌려보낸다.** `Health`가 `Damaged → Changed → Died` 순으로
  알리기 때문에, 안 막으면 사망 순간에 페이즈 전환이 시작돼 무적을 켜고 잘린다

### 보스 체력바와 이름

- `BossHealthBar`는 **대상을 스스로 찾지 않고 `Bind`로 받습니다.** 보스는 방에 들어가는 순간
  만들어지는 인스턴스라, 게임 시작 시점에는 씬을 뒤져도 존재하지 않습니다
- `BossEncounter`가 보스를 만든 직후 물리고, 방을 정리할 때 뗍니다. 재 게이지를 잇는 방식과
  같습니다 — 저쪽은 **플레이어가** 프리팹이라, 이쪽은 **보스가** 프리팹이라 미리 못 겁니다
- **바는 체력 전체가 아니라 지금 페이즈의 몫만 그립니다.** 지금 값인 0.7이면 1페이즈는
  체력 100~70%를 바 100~0%로, 2페이즈는 체력 70~0%를 다시 바 100~0%로 옮깁니다.
  그래서 전환 직전에 바가 **완전히 비고**, 전환이 끝나면 **다시 가득 찹니다**.
  두 페이즈의 몫이 30 대 70으로 어긋나 있어도 바에는 안 드러납니다 — 둘 다 가득 찬 바에서
  0까지 내려갑니다
- 전환 지점을 눈금으로 예고하던 방식은 2026-09-02에 걷어냈습니다. 눈금은 "곧 온다"까지만
  말하지만, **바가 0이 되는 것은 이겼다고 믿게 만듭니다.** 그 믿음이 뒤집히는 것이 2페이즈입니다
- **경계값은 보스에게 물어서 넘깁니다.** UI에 0.5를 적어두면 보스 수치를 바꿨을 때 바가
  옛 기준으로 나뉘고, 그건 에러 없이 밸런스 문제로 오해됩니다
- 이름은 1페이즈 `???`, 2페이즈 `재의 길`입니다. **`???`의 답은 칭호가 아니라 이름이어야
  합니다** — 이 세계에는 고유명이 하나도 없어서(전부 분류명), 하나만 이름을 가지면
  형식만으로 "종류가 아니라 개체"가 전달됩니다
- 2페이즈 이름이 게임 제목인 이유: 재는 **앞서 이 길을 걷다 죽은 것들의 재**입니다.
  죽으면 완전 초기화라는 규칙이 시스템이 아니라 세계관이 됩니다
- 페이즈 신호 경로: `EnemyBoss.EnteredPhase2` → `BossEncounter` → `BossHealthBar.MarkPhase2()`.
  **보스는 화면 구조를 모릅니다.** 사망을 `Health`가 알리고 방이 받는 것과 같은 분리입니다
- `EnteredPhase2`는 전환이 **끝날 때** 웁니다. 시작할 때 울리면 갑옷이 무너지는 것을 보기 전에
  바 색이 먼저 바뀌어 결과를 미리 말합니다
- 프레임은 **게이지 슬롯이 아래쪽 절반**에 있습니다(위 212px이 뿔 장식, 높이의 51.5%).
  프레임 기준으로 위치를 잡으면 항상 "생각보다 낮다"가 됩니다
- 바 폭의 한계를 정하는 것은 **왼쪽 체력바**입니다. 화면 중앙 정렬이라 가운데 최대 폭이 606입니다

## 아트와 임포트 규칙

- 캐릭터 스프라이트는 Point 필터, 압축 없음, Mesh Type `Full Rect`
- 기준 PPU `32`, 기준 해상도 `640×360`, 카메라 orthographic size `5.625`
- 스프라이트 시트는 균등 셀로 재조립하고 발바닥 기준선을 맞춤
- 보스 시트는 `1536×256`, 셀 `256×256`, 가로 6프레임
- 보스 캐릭터는 정면 전시 자세가 아니라 플레이어처럼 몸을 튼 3/4 전투 자세 사용
- 초록 키 배경은 `#00FF00`; 캐릭터와 효과에는 초록 계열 금지
- 픽셀아트는 검은 외곽선, 2~3단 셀 셰이딩, 하드 엣지 사용

현재 보스 시트 경로:

- `Assets/Project/Art/Characters/Boss/AshKing/`
- 플레이어형 정리본: `Raw/PlayerLike/Normalized/`
- 이전 정면 버전 백업: `Raw/FrontFacingBackup/`

## 중요한 에디터 도구

- `AshProjectSetup` — 레이어, 충돌, 카메라와 프로젝트 기본 설정
- `AshSpriteImportRules` — PPU, 필터, 압축 등 임포트 규칙 강제.
  **규칙을 바꾸면 `GetVersion()`의 숫자를 같이 올려야** 기존 에셋이 다시 임포트됩니다
- `AshTextureFormatAudit` — `Tools → 재의 길 → 텍스처 포맷 감사`. 임포터 설정이 아니라
  **임포트된 텍스처의 실제 포맷**을 읽어 포맷별 장수·메모리와 "4의 배수가 아니라 압축이
  막힌 것"을 뽑습니다. 압축 관련 작업을 하면 이걸로 확인합니다
