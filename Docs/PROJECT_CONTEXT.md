# 재의 길 — 프로젝트 컨텍스트

> 마지막 갱신: 2026-08-28

이 문서는 새 작업이나 새 대화에서 프로젝트의 현재 상태를 빠르게 파악하기 위한 요약입니다. 과거 작업 과정은 `DEVELOPMENT_LOG.md`에만 남기고, 여기에는 현재도 유효한 사실과 다음 행동만 유지합니다.

## 한 줄 요약

영구 성장 없이 유물 시너지로 한 판을 완성하는 2D 탑다운 픽셀아트 던전 슬래셔 로그라이크입니다.

## 설계에서 바꾸지 않을 것

- 죽으면 언락·영구 강화 없이 런을 완전히 초기화합니다.
- 반복 동기는 유물 조합과 전투 숙련이 담당합니다.
- 재시작은 상태를 수동 초기화하지 않고 게임 씬을 다시 로드하는 방식입니다.
- 게임플레이 아트는 회색·숯색을 바탕으로 주황 잉걸만 강조색으로 씁니다.
- 공격은 피해보다 예비동작과 회피 가능성이 먼저 읽혀야 합니다.
- 에디터 도구는 메뉴에서 명시적으로 실행하며 씬을 자동 저장하지 않습니다.
- 기존 Unity 에셋을 교체할 때 `.meta`와 GUID를 유지합니다.

## 현재 플레이 흐름

1. `Title`에서 게임 시작
2. `Game`의 **튜토리얼 방**에서 조작을 익히고 아래 문으로 나감
3. 던전 방 전투 → 적 전멸 후 보상 상자 → 개봉 후 문과 출구 활성화
4. 상자에서 **보스 열쇠** 4종을 모으면, 다음 보상을 챙길 때 **부서진 문**이 열림
5. 부서진 문으로 나가면 **보스 방** 진입
6. 보스 처치 → 클리어 유물 드롭 → 획득 시 문 개방 → **문 통과 시 승리로 런 종료**
7. 플레이어가 죽으면 패배로 런 종료
8. `Result`에서 결과 표시 및 재시작

튜토리얼 방과 보스 방은 별도 씬이 아니라 `Game` 씬 안의 방입니다. 씬을 나누면 HUD·인벤토리·플레이어를 복제해야 하고, 복제본이 원본과 어긋나는 위험이 생깁니다.

보스 진입 조건은 방 번호가 아니라 **열쇠**입니다. 두 조건을 같이 두면 열쇠를 다 모았는데 방 번호가 먼저 걸려 보스가 나오고, 어느 쪽으로 갔는지도 알 수 없어서 방 번호 조건은 걷어냈습니다.

승리 흐름은 코드가 모두 연결됐지만 **결과 화면까지 완주 검증은 아직 하지 않았습니다.**

열쇠를 다 모으면 **그 방에서 바로** 부서진 문이 열립니다. 예전에는 보상을 한 번 더 챙겨야 했는데,
상자가 "열렸다"와 "보상을 손에 넣었다"를 신호 둘로 나누면서 같이 풀렸습니다.

## 구현된 시스템

### 코어와 전투

- `GameFlow`, `RunManager`, `RunResultData`로 씬 흐름과 런 결과 관리
- `Health`, `DamageInfo`, `DamageHitbox`를 플레이어와 적이 공유
- 플레이어 이동, 대시, 넉백과 실제 속도 기반 애니메이터 연동
- Ctrl 기본 공격과 Q/W/E/R 스킬
- `SkillData` 상속 구조로 근접·투사체·장판 스킬 분리

### 방과 적

- 잿불 망령: 배회 → 추격 → 예비동작 → 돌진 → 회복 상태 머신
- `ObjectPool<T>` 기반 적 재사용
- `RoomController`, `RoomDoorState`, `RoomExitTrigger`, `RoomSequenceController`
- 전멸 → 상자 → 문 개방 순서를 이벤트로 연결
- 방 이동 시 플레이어의 Rigidbody2D 속도 초기화

### 유물과 인벤토리

- 유물 14종: 일반 10종과 보스/진행 유물 4종
- `RelicData`는 정의, `RelicInstance`는 런마다 결정된 실제 수치를 소유
- 유물 수치는 정의된 범위 안에서 런마다 무작위 결정
- 보관함과 장착 슬롯 3개 분리
- **보스 열쇠 4종은 전용 칸 4개**를 따로 씀 — 진행 표식이 전투 칸을 뺏으면 열쇠를 모을수록 약해집니다
- `T`로 여는 보스 열쇠 화면. 칸을 눌러 빼면 보관함으로 돌아가고 사라지지 않습니다
- 장착된 유물만 효과 적용
- 장착 변경 시 기본값에서 모든 보정치를 다시 계산
- `Health`와 `PlayerStamina`는 기본 최대치 + 유물 보정 구조
- 인벤토리를 열면 시간이 멈추며 `I` 또는 `Tab`으로 닫음

### 재의 왕 보스

- 1페이즈: 거대한 중갑 재의 왕
- 체력 50%에서 갑옷이 무너지고 여성형 진체인 2페이즈로 전환
- 2페이즈 핵심 의미: 갑옷 속 인물이 아니라 재가 왕의 형상을 직접 얻은 상태
- 거리 기반 패턴 선택과 페이즈별 AnimatorController 분리
- 패턴 3종 — 내려찍기(옆으로 피함), 잿불 파도(사이로 피함), **재 폭발**(멀어져서 피함)
- 재 폭발은 2페이즈 전용. 반경 12로 방 바닥 대부분을 덮고 **네 모서리만 안전**하다
- 판정은 그림(좌우 2방향)이 아니라 **실제 방향**을 따름 — 내려찍기 상자를 조준 방향으로 회전
- 공격 시간은 **클립 길이 그대로**, 2페이즈는 `phase2MotionScale`(0.8)로 줄임 (2P 클립이 15fps)
- 2페이즈에서 몸통 콜라이더 **폭만** 0.87배로 줄임 (시트를 재보면 높이는 같고 폭만 줄었다)
- 보스 프리팹: `Assets/Project/Prefabs/Enemy/BossAshKing.prefab`
- 보스 로직: `Assets/Project/Scripts/Enemy/EnemyBoss.cs`
- `EnemyBoss.OnValidate`가 인스펙터 값의 모순을 경고한다 — 시전 사거리가 물러나는 거리보다
  작으면 그 패턴은 영영 안 나오고, 닿는 거리보다 크면 시전해도 헛친다

## 아트와 임포트 규칙

- 캐릭터 스프라이트는 Point 필터, 압축 없음, Mesh Type `Full Rect`
- 기준 PPU `32`, 기준 해상도 `640×360`, 카메라 orthographic size `5.625`
- 스프라이트 시트는 균등 셀로 재조립하고 발바닥 기준선을 맞춤
- 보스 시트는 `1536×256`, 셀 `256×256`, 가로 6프레임
- 보스 캐릭터는 정면 전시 자세가 아니라 플레이어처럼 몸을 튼 3/4 전투 자세 사용
- 초록 키 배경은 `#00FF00`; 캐릭터와 효과에는 초록 계열 금지
- 픽셀아트는 검은 외곽선, 2~3단 셀 셰이딩, 하드 엣지 사용

현재 보스 시트 경로:

- `Assets/Project/Art/Characters/Boss/AshKing/`
- 플레이어형 정리본: `Raw/PlayerLike/Normalized/`
- 이전 정면 버전 백업: `Raw/FrontFacingBackup/`

- `AshTitleSceneBuilder` — 타이틀 연출 구성

- `AshTrainingDummyBuilder` — 허수아비 레이어·콜라이더·컴포넌트 배선

## 스프라이트 시트 도구 (`Tools/`)

PowerShell로 돌리는 이미지 전처리 도구입니다. 원본은 각 폴더의 `Raw/` 아래에 백업됩니다.

- `NormalizeBossSheets.ps1` — 보스 시트 발 라인 정렬, 빈 프레임 복구. `-Only`로 시트 하나만 처리한다
  (전체를 다시 돌리면 이미 정규화된 그림이 `Raw/PreNormalize` 백업을 덮어써 원본을 잃는다)
- `NormalizeDirectionalSheets.ps1` — 8방향 시트(6~8열 × 8행) 셀별 발 라인 정렬
- `InstallPlayerSheets.ps1` — 정규화한 시트를 기존 파일명 자리에 설치(클립 GUID 유지)
- `DefringeCharacterSprites.ps1` — 실루엣에 구워진 밝은 테두리 제거
- `PrepareBossRoomSprite.ps1` — 보스 방 배경의 크로마키 초록 배경을 투명으로 변환
- `RemoveChromaKeyGreen.ps1` — 캐릭터 시트의 크로마키 초록 배경 제거. 발 라인 정렬 전에 먼저 돌린다
- `NormalizeVfxSheets.ps1` — VFX 시트 바닥선 정규화, 피벗을 접지선으로 교체
- `MirrorDamagedPlayerDirections.ps1` — 손상된 방향 행을 대칭 짝의 좌우 반전으로 대체
- `RemoveCrossFrameFragments.ps1` — 칸 경계를 넘어온 이펙트 조각 제거

도구는 모두 미리보기가 기본이고 `-Apply`를 붙여야 실제로 쓴다. 원본은 각 폴더의 `Raw/` 아래에 백업된다.

## 알려진 미해결 — 그림 재생성이 필요한 것

아래 4개 방향은 어두운 픽셀이 원본에서부터 빠져 있어 도구로 복원할 수 없습니다.
대칭 짝이 없거나(N) 짝도 손상된 경우입니다.

| 시트 | 방향 | 보이는 상황 |
| --- | --- | --- |
| `player_walk` | N | 위로 걸을 때 |
| `player_dash_hit` | N | 위로 대쉬할 때 |
| `player_ultimate` | SW, SE | 좌하·우하 궁극기 |

다시 뽑을 때는 **셀을 키우거나 참격·잔상을 별도 VFX로 분리**합니다. 256px 셀에 캐릭터와
큰 궤적을 같이 그리면 칸을 넘어가고, 그게 지금까지 조각이 섞인 원인입니다.
Q 스킬은 이미 이펙트를 프리팹으로 분리한 구조라 그대로 참고하면 됩니다.

## 내일 할 일 — 2026-08-29

### 1. 열쇠 개수 HUD — 먼저

지금은 `T`를 눌러야만 열쇠 수가 보이고, **`T`가 있다는 걸 알려주는 곳이 어디에도 없습니다.**
플레이어는 "왜 보스가 안 나오지"를 알 방법이 없습니다. 진행이 막히는 문제라 값이 가장 큽니다.

### 2. 사운드 시스템

`AudioSource`/`AudioClip`/`AudioMixer` 사용처가 프로젝트에 **하나도 없습니다.**
`AudioMixer`와 공용 재생 구조를 먼저 짜고 타격·피격·보스 패턴에 붙입니다.

### 3. 일시정지(`ESC`)와 설정 화면

설정의 대부분이 볼륨이라 **사운드보다 먼저 만들면 헛돕니다.** 조절할 대상이 없으면
빈 껍데기를 만들어놓고 나중에 다시 열어 배선해야 합니다. 설정은 일시정지 메뉴 안에 둡니다.

### 4. 밸런스

- 보스까지 17방 — 열쇠 4개 × 25%면 기대 상자 16개. 스코프의 "1회 8~12분"과 안 맞습니다.
  열쇠 수 / 확률 / 방 개수 중 하나를 정해야 합니다.
- 보스 체력 40 — 2페이즈(20)가 3~6초라 궁극기(쿨다운 12초)를 한 번 볼까 말까입니다.
  60으로 올리면 2페이즈가 8~10초가 되어 패턴 3종이 다 나옵니다.

### 5. 승리 흐름 완주 검증

튜토리얼 → 던전 → 열쇠 4개 → 부서진 문 → 보스 → 유물 → 문 → 결과.
코드는 다 연결됐으나 **끝까지 도달한 적이 없습니다.**

### 6. 그 밖에 남은 것

- **카메라 상수 불일치** — `AshProjectSetup.CameraOrthographicSize`는 5.625인데 `Game.unity`는 14입니다.
  그 도구를 다시 돌리면 카메라가 확 당겨져 보스 방 구도가 깨집니다. 어느 쪽이 맞는지 정해야 합니다.
- `Skill_Q_GroundSlam`의 damage가 0입니다. 의도인지 확인 필요
- 손상 4방향 재생성 (아래 "알려진 미해결")
- 튜토리얼 방 벽 콜라이더 — 캠프 배경 1920×1080인데 벽은 던전 방(1678×937) 기준입니다
- 유물 무작위 수치와 장착 3칸 조합 밸런스 확인
